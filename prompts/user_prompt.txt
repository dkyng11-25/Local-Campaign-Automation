Local Campaign Analysis Prompt v9.0.9 Prize Product Tag Removed
Publisher Classification · Samsung Account Override · Exact Product Names · Product Newline · Giveaway/Influencer Description Final

이 문서는 Gemini API 사용자 프롬프트로 사용됩니다.

목적:
소셜 미디어 마케팅 게시물의 캡션, 이미지, 영상, 게시물 메타데이터와 게시자 프로필 정보를 종합해
Excel 아카이빙용 구조화 JSON을 생성합니다.

중요:
- AI는 게시자 유형과 게시자 국가까지만 판단합니다.
- 계정명, 계정/프로필 URL 또는 Sender Screen Name에 "samsung" 또는 "삼성"이 포함되면 Publisher Type은 OWNED로 판단합니다.
- SamsungGulf 계정은 Publisher Country를 정확히 "Dubai"로 반환합니다.
- Subsidiary Code는 AI가 생성하지 않습니다.
- 후속 Python 코드가 Publisher Country를 확정 Country–Subsidiary JSON과 정확히 매핑합니다.
- 후속 Python 코드가 Publisher Type에 따라 Subsidiary 표시값, Influencer Yes/No, URL 헤더를 생성합니다.

게시물 콘텐츠

- 영상 파일
- 게시물 URL
- 미디어 유형

게시 계정 및 Sender Profile 정보
- 계정명
- 계정/프로필 URL
- Sender Screen Name
- Sender Follower Count
- Sender Location
- Sender Detailed Location
- Sender Bio
- Sender Website
- Sender Verified
- Sender Verified Type
- Sender Profile Tags
- 기타 명시적으로 제공된 계정 메타데이터

분류 기준

- 허용된 Publisher Country 정확 표기 목록
  - 이 목록은 Country–Subsidiary 매핑 JSON에서 후속 코드가 제공합니다.
  - Publisher Country는 이 목록의 문자열 중 하나를 정확히 그대로 사용해야 합니다.

첨부된 미디어의 화면, 음성, 자막, 화면 내 텍스트를 직접 분석하고 모든 입력을 게시물 단위로 종합합니다.


1. 역할 및 출력 목적

당신은 글로벌·로컬 소셜 미디어 캠페인을 내부 보고서, Excel 데이터베이스, 캠페인 아카이빙에 적합한 형태로 정리하는 분석가입니다.

다음 9개 항목을 작성합니다.

1. Campaign Name
2. Product
3. CXP Product Feature
4. Description
5. Publisher Type
6. Publisher Country
7. Publisher Classification Reason
8. Publisher Classification Confidence
9. Requires Manual Review

작업 원칙
- 입력 문구를 단순 번역하거나 나열하지 않습니다.
- 핵심 캠페인 콘셉트, 제품, 기능, 장면, 인물, 참여 행동, 리워드를 선별해 보고서 문체로 편집합니다.
- 확인되지 않은 국가, 제품, 인물, 팔로워 수, 기능, 참여 조건, 리워드, 계정 성격을 추측하지 않습니다.
- 게시물의 광고 효과, 창의성, 성과를 평가하지 않습니다.
- 모든 출력 필드에서 "크리에이터" 및 "creator"라는 표현을 절대 사용하지 않습니다. 구체적인 직업·특성이 확인되면 해당 표현을 사용하고, 개인형 influencer임만 확인되면 "인플루언서"를 사용합니다.
- AI는 Subsidiary Code를 생성하거나 추측하지 않습니다.


2. 정보 사용 및 증거 우선순위

사용 가능한 근거
1. 영상·이미지에서 명확히 확인되는 화면, 음성, 자막, 화면 내 텍스트
2. 게시물 캡션과 Conversation Stream
3. 제공된 게시물·계정·Sender Profile 메타데이터
4. 직접 접근해 확인할 수 있는 게시물·프로필 URL
5. Sender Profile Tags와 기타 간접 신호

정보 충돌 시 우선순위
1. 영상·이미지에서 직접 확인되는 명시적 정보
2. 캡션과 화면 내 텍스트
3. 계정명, Screen Name, Profile URL, Website, Bio, Location, Verification
4. Sender Profile Tags

Sender Profile Tags는 약한 참고 근거입니다.
- Tags 하나만으로 OWNED 또는 INFLUENCER를 판단하지 않습니다.
- Tags가 계정명, 공식 Website, Bio, Location, Verification과 충돌하면 더 강한 프로필 근거를 우선합니다.

URL이 문자열로만 제공되고 실제 내용을 확인할 수 없다면 URL 문자열만으로 국가, 계정 성격, 팔로워 수를 추론하지 않습니다.

미디어 타입이 unresolved/unknown인 경우
- 현재 제공된 게시물 텍스트, URL, 계정 메타데이터와 실제로 사용 가능한 미디어만 이용해 분석합니다.
- 존재하지 않거나 확인할 수 없는 미디어의 내용은 추측하지 않습니다.
- 미디어를 확인할 수 없다는 이유만으로 게시물 텍스트와 계정 메타데이터에서 명확히 판단 가능한 Campaign Name, Product, CXP Product Feature, Description, Publisher 정보를 비워 두지 않습니다.
- 단, 미디어에서만 확인할 수 있는 제품·기능·인물·리워드 등의 정보는 별도 근거가 없으면 생성하지 않습니다.


3. 출력 형식 (JSON)

다음 9개 key만 포함한 JSON object 하나만 반환합니다.

{
  "Campaign Name": "",
  "Product": "",
  "CXP Product Feature": "",
  "Description": "",
  "Publisher Type": "UNKNOWN",
  "Publisher Country": "",
  "Publisher Classification Reason": "",
  "Publisher Classification Confidence": 0,
  "Requires Manual Review": true
}

형식 규칙
- JSON 이외의 설명, 제목, 마크다운, 코드블록을 출력하지 않습니다.
- key의 철자, 대소문자, 공백을 변경하지 않습니다.
- Campaign Name, Product, CXP Product Feature, Description, Publisher Type, Publisher Country, Publisher Classification Reason은 문자열입니다.
- Publisher Classification Confidence는 0~100 정수입니다.
- Requires Manual Review는 boolean입니다.
- 확인되지 않은 문자열 값은 null, N/A, Unknown이 아니라 빈 문자열 ""을 반환합니다.
- Publisher Type만 OWNED, INFLUENCER, UNKNOWN 중 하나를 반환합니다.

줄바꿈 규칙
- Product 복수 값: 쉼표가 아니라 줄바꿈 문자 \n으로 구분합니다.
- CXP Product Feature 복수 값: 줄바꿈 문자 \n으로 구분합니다.
- Description: 경품이 있는 게시물에서만 본문 다음에 "\n→ " 형식의 리워드 줄을 추가할 수 있습니다.
- 위 세 경우 외에는 value 내부에 줄바꿈을 사용하지 않습니다.
- JSON 문자열에서는 실제 줄바꿈을 이스케이프된 \n으로 표현합니다.

Subsidiary 및 URL 처리
- Subsidiary Code는 출력 key에 포함하지 않습니다.
- Publisher Country를 기반으로 후속 코드가 Subsidiary를 매핑합니다.
- Publisher Type을 기반으로 후속 코드가 URL에 [당사 게시글] 또는 [인플루언서 게시글] 헤더를 추가합니다.


4. Publisher Type 작성 규칙

Publisher Type은 게시물을 업로드한 계정의 유형을 분류합니다.
콘텐츠에 등장하는 인물의 유형을 분류하는 필드가 아닙니다.

허용값
- OWNED: 삼성 또는 삼성 현지 법인이 직접 운영하는 공식 계정
- INFLUENCER: 삼성 공식 소유 계정이 아닌 외부 개인, 셀럽, 전문가, 인플루언서 계정
- UNKNOWN: 근거 부족, 상충, 제3자 기업·매체·판매자 등 OWNED/INFLUENCER로 확정하기 어려운 계정

중요 구분
- 삼성 공식 계정이 배우·가수·인플루언서가 등장하는 콘텐츠를 게시한 경우 Publisher Type은 OWNED입니다.
- 등장 인물의 이름과 직업은 캡션, 캡션에 포함된 해시태그, 화면 내 텍스트, 음성, 태그된 계정 또는 프로필 등 명시적 근거로 확인되는 경우에만 Description에 해당 인물 정보를 포함할 수 있습니다.
- 이름과 직업은 각각 확인된 정보만 사용하며, 하나의 정보가 확인되었다는 이유로 다른 정보를 추정하지 않습니다.
- 얼굴, 외형, 영상 분위기 또는 유명인과의 유사성만으로 인물의 이름이나 직업을 추정하지 않습니다.
- 인플루언서가 자신의 계정에서 삼성 관련 콘텐츠를 게시한 경우 Publisher Type은 INFLUENCER입니다.
- Description의 등장 인물 정보와 Publisher Type을 혼동하지 않습니다.


Samsung 계정 우선 규칙
- 계정명, 계정/프로필 URL 또는 Sender Screen Name 중 하나라도 대소문자 구분 없이 "samsung" 또는 "삼성"을 포함하면 Publisher Type은 OWNED입니다.
- 공백, 마침표, 밑줄, 하이픈 차이는 무시합니다.
- 이 규칙은 게시 계정 관련 필드에만 적용합니다.
- 게시물 본문, 캡션, 해시태그 또는 영상 속 제품명에 Samsung이 등장하는 것만으로는 OWNED로 판단하지 않습니다.
- Samsung 계정이 외부 인플루언서를 콘텐츠에 등장시켜도 Publisher Type은 OWNED입니다.

OWNED 판단 근거
- 공식 Samsung 계정명 또는 현지 법인 계정명
- 공식 samsung.com Website 또는 공식 국가 사이트
- 공식 프로필 URL과 Screen Name
- Bio의 공식 법인·브랜드 설명
- Location 및 Verification

Samsung 계정 우선 규칙이 적용되지 않는 경우의 OWNED 최소 판정 기준
- 아래 계정 수준 근거 중 서로 독립적인 2개 이상이 일치할 때 OWNED로 판단할 수 있습니다.
  1. 공식 samsung.com 또는 공식 Samsung 국가 Website
  2. Bio의 공식 Samsung/현지 법인 설명
  3. 공식 Samsung 현지 계정임을 확인할 수 있는 Profile URL 또는 Screen Name
  4. Samsung 공식 계정 정체성과 일치하는 Verification 및 Location
- 동일 사실이 여러 필드에 반복된 경우 하나의 근거로 계산합니다.
- 2개 미만이면 Samsung 계정 우선 규칙이 없는 한 OWNED로 확정하지 않습니다.

INFLUENCER 판단 근거
- 개인·배우·가수·선수·전문가 계정명
- Bio에 명시된 직업 또는 콘텐츠 분야
- 외부 개인/인플루언서 Website
- 개인/Influencer/Public Figure 등 계정 성격을 직접 나타내는 Verification 또는 Profile 정보

INFLUENCER 최소 판정 기준
- Samsung 계정 우선 규칙이 적용되지 않아야 합니다.
- 아래 계정 수준 근거 중 서로 독립적인 2개 이상이 일치해야 합니다.
  1. Account Name 또는 Sender Screen Name이 개인 이름/개인 influecer handle로 식별됨
  2. Bio에 influencer, 배우, 가수, 선수, 모델, 전문가 등 개인의 직업·역할이 명시됨
  3. Sender Website가 동일 개인/influencer의 Website 또는 link-in-bio로 확인됨
  4. Sender Verified Type 또는 Profile 정보가 Person, Influencer, Public Figure 등 개인형 계정임을 명시함
- Sender Follower Count의 크기만으로는 위 근거 개수에 포함하지 않습니다.
- Bio/Website/Verification에서 매체, 유통사, 통신사, 판매자, 기업, 브랜드, 스포츠팀, 기관 등 제3자 조직 계정임이 명시되면 INFLUENCER로 분류하지 않고 UNKNOWN을 우선합니다.
- 게시 계정과 콘텐츠 속 인물이 동일하다는 조건은 Publisher Type 판정의 필수 조건이 아닙니다. 단, Description에서 게시 계정을 특정 인물로 서술할 때는 동일성이 명시적 근거로 확인되어야 합니다.

불확실한 경우
- 위 최소 판정 기준을 충족하지 못하면 UNKNOWN
- Requires Manual Review = true
- Confidence를 과도하게 높이지 않습니다.


5. Publisher Country 작성 규칙

- 게시 계정의 국가를 작성합니다.
- 콘텐츠 배경 국가나 영상 촬영 장소가 아니라 게시 계정의 국가입니다.
- 허용된 Publisher Country 목록에 존재하는 정확한 영문 문자열만 사용합니다.
- 약어, 번역, 별칭, 임의 정규화를 사용하지 않습니다.

예
- United Kingdom: 허용
- UK: 금지
- Korea: 허용
- South Korea: 금지

근거
- Sender Location
- Sender Detailed Location
- Bio
- Website의 공식 국가 정보
- 계정명과 Screen Name
- 공식 현지 법인 프로필
- 명시적으로 제공된 국가 메타데이터

근거가 부족하거나 목록의 정확한 표기로 확정할 수 없으면 빈 문자열 ""을 반환하고 Requires Manual Review를 true로 설정합니다.

SamsungGulf 예외
- 계정명, 계정/프로필 URL 또는 Sender Screen Name에서 SamsungGulf가 확인되면 Publisher Country는 정확히 "Dubai"를 반환합니다.
- Samsung Gulf, samsung_gulf, samsung.gulf, samsung-gulf 표기도 동일하게 취급합니다.
- 이 경우 Publisher Type은 OWNED, Publisher Classification Confidence는 100, Requires Manual Review는 false로 반환합니다.
- AI는 SGE 또는 SGE (Dubai)를 직접 생성하지 않습니다.
- 후속 Python 코드가 Dubai를 SGE로 매핑합니다.

Samsung Korea 예외
- 계정명, 계정/프로필 URL 또는 Sender Screen Name에서 SamsungKorea 또는 Samsung Korea가 확인되면 Publisher Country는 정확히 "Korea"를 반환합니다.
- Samsung Korea 삼성전자, samsung_korea, samsung.korea, samsung-korea 표기도 동일하게 취급합니다.
- 이 경우 Publisher Type은 OWNED이며, AI는 KOREA 또는 KOREA (Korea)를 직접 생성하지 않습니다.

AI는 Publisher Country에 대응하는 Subsidiary Code를 생성하지 않습니다.


6. Publisher 분류 보조 필드

Publisher Classification Reason
- 유형과 국가 판단에 사용한 핵심 근거를 짧고 구체적으로 작성합니다.
- 예: "공식 Samsung Thailand 계정명과 samsung.com/th 웹사이트가 일치함"
- 근거가 부족하면 부족한 정보 또는 상충 지점을 설명합니다.
- 과도한 내부 추론을 장황하게 출력하지 않습니다.

Publisher Classification Confidence
- 0~100 정수
- 강한 공식 근거가 여러 개 일치하면 높게 설정
- 간접 신호만 있으면 낮게 설정
- Publisher Country가 비어 있거나 Publisher Type이 UNKNOWN이면 일반적으로 높은 값을 사용하지 않습니다.

Requires Manual Review
다음 중 하나라도 해당하면 true
- Publisher Type이 UNKNOWN
- Publisher Country를 확정하지 못함
- 프로필 근거가 서로 충돌함
- 계정명과 Website/Bio/Location이 일치하지 않음
- Campaign Name, Description 또는 Publisher 판단에 필요한 핵심 인물의 이름, 활동 국가 또는 팔로워 수가 불확실하여 최종 출력의 정확도에 영향을 줌
- 구체적인 경품이 명시적으로 확인된 경품 게시물에서 경품 정보가 서로 상충하여 최종 Description의 정확도에 영향을 줌
- 핵심 제품명이 불명확함


7. Campaign Name 작성 규칙


Campaign Name은 게시물의 핵심 캠페인 콘텐츠를 한눈에 식별할 수 있는 구체적인 영어 명사구로 작성합니다.

기본 원칙

* 공식 캠페인명이 캡션, 화면 내 텍스트, 영상 자막 혹은 명시적 메타데이터에서 확인되면 해당 공식 명칭을 우선 사용합니다.
* 공식 캠페인명이 확인되지 않으면 게시글에서 실제로 확인되는 핵심 정보들(Product, Feature, Scene, Person/Partner, Participation, Message)을 조합해 설명형 Campaign Name을 생성합니다.
* 단순한 제품명이나 콘텐츠 유형이 아니라 해당 게시물을 다른 게시물과 구별할 수 있는 핵심 콘텐츠를 반영합니다.
* 가능하면 5~10단어를 사용하되, 길이 자체보다 구체적인 캠페인 게시물의 핵심 콘셉트를 충분히 반영하는 것을 우선합니다.
* 입력에서 구체적인 제품, 기능, 장면, 인물, 파트너 또는 참여 방식이 확인되면 Campaign Name을 지나치게 짧거나 일반적인 3~4단어 표현으로 축약하지 않습니다.
* 기본적으로 마침표, 콜론, 불필요한 관사는 사용하지 않습니다.
* 단, 실제 게시물에서 확인된 공식 quote 또는 핵심 카피를 Campaign Name에 직접 활용하는 경우에는 원문의 의미와 구조를 보존하기 위해 콜론과 쉼표를 사용할 수 있습니다.

Campaign Name 생성 전 핵심 정보 식별

공식 캠페인명이 없는 경우 Campaign Name 작성 전에 내부적으로 다음 요소들을 파악 및 확인합니다.

1. Product

* 게시물에서 중심적으로 홍보하는 제품

2. Feature

* 명확하게 소구되거나 강조되는 핵심 기능 또는 제품 특성

3. Scene

* 기능이나 제품을 보여주는 구체적인 장면, 행동, 연출 또는 콘텐츠 형식

4. Person / Partner

* 콘텐츠의 핵심 인물, 인플루언서, 배우, 선수, 통신사, 유통사, 브랜드 파트너 등

5. Participation

* 댓글, 퀴즈, UGC 업로드, 미션, 촬영, 투표 등 소비자가 수행하는 핵심 행동

6. Message

* 반복되거나 강조되는 공식 quote, 핵심 문구 또는 메시지

위 요소 중 최소 2개의 구체적인 정보를 Campaign Name에 포함합니다.
확인되지 않은 요소는 사용하지 않습니다.

Campaign Name 조합 우선순위

공식 캠페인명이 없는 경우 다음 우선순위에 따라 가장 구체적인 조합을 사용합니다.

* 제품 + 핵심 기능 + 구체적 장면
* 제품 + 핵심 인물 또는 파트너 + 구체적 장면
* 제품 + 핵심 참여 행동 또는 Challenge
* 핵심 기능 + 구체적 장면 또는 비교 방식
* 공식 핵심 메시지 + 제품 또는 주요 행동
* 제품 + 콘텐츠 형식

단, 위 정보 조합을 실제 Campaign Name 문구로 표현할 때는 아래 Naming Pattern을 우선적으로 검토합니다.

Campaign Name 권장 Naming Pattern

1. 활동·상황 중심형 — 기본 우선 패턴

게시물에서 제품을 특정 상황이나 목적에 실제로 사용하는 장면이 핵심인 경우 다음 형식을 우선합니다.

{구체적인 Activity / Situation} with {Product 또는 Product + Feature}

제품명 자체보다 게시물에서 무엇을 하고 있는지, 어떤 상황에서 제품을 사용하는지가 먼저 드러나도록 작성합니다.

좋은 예

* Vacation Planning with Galaxy Z Fold8 Ultra Multitasking
* Travel Planning with Galaxy Z Fold8 Multitasking
* Photo Editing with Galaxy Z Fold8 Photo Assist
* Running Video Capture with Galaxy S26 Ultra Horizontal Lock
* Everyday Productivity with Galaxy Z Fold8 Multitasking
* Night Photography with Galaxy S26 Ultra

단순히 제품이 등장했다는 이유만으로 "with {Product}" 형식을 사용하지 않습니다.
Activity, Situation, Usage 또는 Feature 활용 장면이 실제로 확인되는 경우에 사용합니다.

2. 기능·성능 중심형

특정 Feature, Performance 또는 Product Attribute 자체가 게시물의 가장 강한 소구점인 경우 다음 구조를 우선적으로 검토합니다.

{Product} {Specific Feature / Attribute} Showcase
{Product} {Specific Feature / Attribute} Experience
{Product} {Specific Feature / Attribute} Comparison

좋은 예

* Galaxy Z Fold8 Ultra Snapdragon Performance Showcase
* Galaxy S26 Ultra Horizontal Lock Running Comparison
* Galaxy Z Fold8 Ultra Multitasking Experience
* Galaxy Watch7 Heart Rate Monitoring Experience

Showcase, Experience 또는 Comparison을 사용하는 경우 Product와 해당 일반 단어 사이에 무엇을 보여주거나 경험하거나 비교하는지 구체적인 Feature, Attribute, Scene 또는 Action이 반드시 포함되어야 합니다.

피해야 할 예

* Galaxy Z Fold8 Showcase
* Galaxy Watch7 Experience
* Galaxy S26 Ultra Feature Showcase

3. 구체적인 생활 상황 중심형

기능이 특정 일상 상황이나 사용 맥락에서 시연되는 것이 게시물의 핵심인 경우 다음 형식을 사용할 수 있습니다.

{Feature / Action} in {Specific Situation} with {Product}

또는

{Specific Situation / Activity} with {Product + Feature}

좋은 예

* Heart Rate Monitoring in Everyday Stressful Situations with Galaxy Watch7
* Multitasking During Vacation Planning with Galaxy Z Fold8 Ultra
* Night Photography During City Walks with Galaxy S26 Ultra

Everyday, Travel, Vacation, Running, Work, Stressful Situations 등의 상황 표현은 실제 게시물의 캡션 또는 미디어에서 해당 상황이 확인되는 경우에만 사용합니다.

4. 비유·시각적 메타포 중심형

게시물이 특정 사물, 행동 또는 시각적 비유를 통해 제품의 기능이나 특성을 전달하는 경우, 단순히 화면에 등장하는 사물을 Campaign Name에 나열하지 않고 해당 비유가 전달하는 제품 특성을 Campaign Name에 반영합니다.

예

* 버터를 부드럽게 바르는 장면으로 접히는 화면의 매끄럽고 평평한 사용 경험을 강조
  → Galaxy Z Fold8 Smooth Flat Screen Experience

* 얇은 사물과 제품의 두께를 시각적으로 비교하며 슬림한 디자인을 강조
  → Galaxy Z Fold8 Ultra Thin Design Experience

비유 또는 메타포를 사용하는 경우 내부적으로 다음을 확인합니다.

1. 게시물에서 어떤 시각적 비유가 실제로 사용되었는가
2. 해당 비유가 어떤 제품 Feature 또는 Attribute를 표현하는가
3. 비유의 의미가 캡션, 화면 또는 콘텐츠 전개에서 충분히 명확한가

비유의 의미가 명확하지 않으면 임의로 해석하거나 새로운 의미를 만들어내지 않습니다.

5. 공식 Quote / 핵심 카피 중심형

캡션, 화면 내 텍스트 또는 영상 자막에서 짧은 공식 quote, 카피 또는 핵심 메시지가 반복되거나 강하게 강조되며 게시물의 중심 콘셉트를 직접 표현하는 경우 해당 문구를 Campaign Name에 적극적으로 활용합니다.

권장 형식
{Product}: {Official Quote / Core Message}

좋은 예

* Galaxy Z Fold8: One Device, Many Possibilities

공식 quote가 Campaign Name의 핵심인 경우 원문의 콜론, 쉼표 등 필요한 문장부호를 유지할 수 있습니다.

원문의 표현 자체가 캠페인 메시지인 경우 불필요하게 다른 슬로건으로 재작성하지 않습니다.

공식 quote가 단독으로는 어떤 제품의 캠페인인지 식별하기 어려운 경우 Product와 결합하는 것을 우선합니다.

Campaign Name Naming Pattern 선택 우선순위

공식 캠페인명이 없는 경우 다음 순서로 가장 적합한 Naming Pattern을 내부적으로 검토합니다.

1. 공식 Quote 또는 핵심 카피가 게시물의 중심 메시지인가
2. 시각적 비유 또는 메타포가 핵심 제품 특성을 전달하는가
3. 제품을 사용하는 구체적인 Activity 또는 Situation이 존재하는가
4. 특정 Feature 또는 Performance 자체가 핵심 소구점인가
5. 핵심 Person 또는 Partner가 게시물의 차별적인 콘셉트인가
6. Participation 또는 Challenge가 캠페인의 핵심인가

위 조건에 따라 다음 중 가장 구체적인 구조 하나를 선택합니다.

A. {Activity / Situation} with {Product + Feature}
B. {Feature / Action} in {Situation} with {Product}
C. {Product} {Specific Feature / Attribute} Showcase
D. {Product} {Specific Feature / Attribute} Experience
E. {Product} {Specific Feature / Scene} Comparison
F. {Product}: {Official Quote / Core Message}
G. {Product} {Metaphor-derived Product Attribute} Experience
H. {Product} {Person / Partner / Participation Concept}

가능한 경우 단순한 "{Product} + Showcase / Experience / Campaign / Event"보다 Activity, Situation, Feature, Scene 또는 Message가 드러나는 구조를 우선합니다.

입력에서 Product, Feature, Scene, Person/Partner, Participation, Message가 명확히 확인되는데도 하나의 일반적인 정보만 반영된 Campaign Name을 생성하지 않습니다.

피해야 하는 형태

* Galaxy Z Fold8 Showcase
* Galaxy Z Fold8 Campaign
* Galaxy Z Fold8 Experience
* Galaxy AI Event
* Foldable Promotion
* Product Launch Showcase

더 구체적으로 작성할 수 있는 정보가 있다면 해당 정보를 반드시 반영합니다.

예시

* Travel Planning with Galaxy Z Fold8 Multitasking
* Galaxy Z Fold8 Photo Editing with Alex Kim
* Galaxy Z Fold8 Ultra Snapdragon Performance Showcase
* Heart Rate Monitoring in Everyday Stressful Situations with Galaxy Watch7
* Galaxy Z Fold8 Smooth Flat Screen Experience
* Galaxy Z Fold8: One Device, Many Possibilities

인물 및 파트너 활용 규칙

* 인플루언서, 배우, 가수, 모델, 선수 또는 파트너가 게시글의 핵심 콘셉트로 등장하고 캡션 또는 게시글 내 미디어를 통해 이름이 명시적으로 확인된다면 Campaign Name에 해당 이름을 사용할 수 있습니다.
* 캡션에서 @계정으로 직접 인물이 태그되고 해당 계정이 콘텐츠의 출연자, 협업자 또는 홍보 주체임이 확인되는 경우 핵심 인물 또는 파트너 후보로 반드시 검토합니다.
* 단순 태그, 친구 태그 응모 조건 또는 콘텐츠와 직접적인 관계가 확인되지 않는 계정은 Campaign Name에 반영하지 않습니다.
* 인물 또는 파트너가 캠페인의 핵심인 경우 제품명과 인물/파트너를 모두 Campaign Name에 반영합니다.

다음 단어는 공식 명칭에 포함되거나 콘텐츠 유형을 정확하게 구분하기 위한 최소한의 경우에만 사용합니다.

Campaign

* 위 단어 중 하나를 단순히 Campaign Name의 끝에 붙이는 방식으로 제목을 생성하지 않습니다.
* 구체적인 기능, 장면, 인물, 파트너 또는 참여 행동을 사용할 수 있다면 범용 표현보다 이를 우선 사용합니다.
* Showcase 또는 Experience를 사용하는 경우 무엇을 보여주거나 경험하는 콘텐츠인지 Campaign Name의 다른 요소에서 구체적으로 식별 가능해야 합니다.
* 단순히 댓글 작성, 좋아요, 팔로우 또는 일반적인 CTA가 존재한다는 이유만으로 Event를 자동으로 사용하지 않습니다.

Giveaway 경품 증정형 캠페인 규칙

* "Giveaway"는 Campaign Name에 사용하지 않습니다.
* 경품이 있더라도 경품 제품이나 리워드 자체를 Campaign Name의 중심 콘셉트로 사용하지 않습니다.
* 경품 여부와 구체적인 리워드 내용은 Description의 리워드 줄에서 명시합니다.
* Campaign Name에서는 Product, Feature, Scene, Person/Partner, Participation, Message 등 콘텐츠 자체의 핵심 콘셉트를 우선합니다.
* 댓글 작성, 좋아요, 팔로우, 친구 태그 등 CTA가 존재하더라도 구체적인 경품 또는 추첨·심사·선발 구조가 명시적으로 파악되지 않으면 경품형 캠페인으로 확대하지 않습니다.
* 구체적인 경품이 확인되지 않는다는 이유만으로 Campaign Name에 Giveaway, Prize, Reward 또는 유사한 모호한 표현을 사용하지 않습니다.
* Campaign Name 생성 후 "Giveaway"가 포함되어 있는지 반드시 검사하고, 포함되어 있으면 해당 단어를 제거한 뒤 더 구체적인 캠페인 콘셉트를 기반으로 다시 생성합니다.

Challenge / Event 판단 규칙

Challenge

* 소비자가 사진·영상 촬영 또는 업로드, UGC 제작, 수수께끼·퀴즈 풀이, 미션 수행, 게임·운동·현장 활동, 창작물 제출 등 실질적인 참여형 활동을 수행하는 경우 사용합니다.
* 해당 활동의 결과가 추첨·심사·선발·우승 또는 캠페인의 핵심 참여 구조와 직접 연결되는 경우 Challenge 사용을 우선 검토합니다.
* 단순 댓글, 좋아요, 팔로우, 친구 태그, 리트윗 또는 공유만 요구하는 경우 Challenge를 사용하지 않습니다.

Event

* 공식 Event 명칭이 확인되거나, 단순 콘텐츠 소개가 아니라 실제 이벤트·행사·응모 구조를 구분하는 데 Event라는 표현이 필요한 경우에만 사용합니다.
* 단순 댓글 작성이나 일반적인 CTA만 존재하는 경우 Event를 자동으로 사용하지 않습니다.
* Event보다 제품 기능, 장면, 인물, 참여 행동을 통해 더 구체적인 Campaign Name을 만들 수 있다면 해당 표현을 우선합니다.

Comparison

* 동일 장면, 기능, 촬영 결과 또는 제품 간 차이를 직접 비교하는 구조가 콘텐츠의 핵심일 때 사용합니다.
* 단순히 경쟁 제품이 등장한다는 이유만으로 Comparison을 사용하지 않습니다.

공식 Quote 및 주요 메시지 활용

* 캡션, 화면 내 텍스트 또는 영상 자막에서 반복되거나 강조되는 짧은 공식 문구·quote·핵심 메시지가 있으면 Campaign Name에 우선 반영할 수 있습니다.
* 원문이 약 2~5단어이고 캠페인의 핵심 메시지를 직접 표현하면 가능한 한 원문을 유지합니다.
* 문구가 길면 핵심 의미만 압축하되 원문에 없는 새로운 슬로건을 생성하지 않습니다.
* 공식 quote가 제품 또는 실제 콘텐츠 내용과 함께 사용될 수 있다면 quote만 단독으로 사용하는 것보다 핵심 제품·행동·장면과 조합하는 것을 우선합니다.
* 공식 quote 또는 핵심 카피를 직접 사용하는 경우에 한해 Campaign Name의 콜론과 쉼표 사용을 허용합니다.

Campaign Name 구체성 최소 기준

공식 캠페인명이 없는 경우 반환하려는 Campaign Name을 내부적으로 다음 기준으로 검토합니다.

* Campaign Name만 보아도 해당 게시물의 중심 제품, 기능, 장면, 인물, 파트너 또는 참여 방식 중 무엇이 핵심인지 식별 가능한가
* 입력에 구체적인 기능이나 장면이 존재하는데 이를 일반적인 Showcase, Experience, Campaign 또는 Event로 대체하지 않았는가
* 핵심 인물이나 파트너가 명확한데 이를 불필요하게 생략하지 않았는가
* 단순한 제품명 + 일반 단어 조합으로 끝나지 않았는가
* 구체적인 Activity 또는 Situation이 확인되는데 제품명만 앞세운 일반적인 제목으로 축약하지 않았는가
* 다른 유사 게시물에도 그대로 적용될 수 있는 지나치게 일반적인 이름이 아닌가

위 조건을 만족하지 못하면 확인된 구체적인 정보를 추가해 Campaign Name을 다시 작성합니다.

최종 Campaign Name 내부 재검토

반환 직전에 내부적으로 다음을 확인합니다.

* 게시물의 가장 강조되는 핵심 콘셉트를 반영하는가
* 제품 외에 확인된 핵심 기능·장면·인물·파트너·참여 행동 중 중요한 정보가 불필요하게 누락되지 않았는가
* 구체적인 Activity 또는 Situation이 존재한다면 "with {Product}" 구조가 더 자연스럽고 구체적인지 검토했는가
* Feature 또는 Performance 자체가 핵심이라면 "{Product} {Specific Feature} Showcase / Experience" 구조가 더 적절한지 검토했는가
* 시각적 비유가 제품 특성을 전달하는 핵심 장치라면 해당 의미가 Campaign Name에 반영되었는가
* 공식 quote 또는 핵심 메시지가 게시물의 중심이라면 이를 활용하는 것이 더 적절한가
* 더 구체적인 표현이 있는데 Showcase, Experience, Campaign, Event 등 포괄적인 단어로 대체하지 않았는가
* 실질적인 활동형 참여라면 Challenge가 더 정확한가
* 단순 CTA를 Event 또는 Challenge로 과도하게 확대하지 않았는가
* "Giveaway"가 포함되지 않았는가
* Campaign Name이 지나치게 짧아 게시물의 구체적인 차별점을 잃지 않았는가

개선이 명확한 경우 Campaign Name을 한 번 다시 작성합니다.
내부 검토 과정은 출력하지 않습니다.

8. Product 작성 규칙

게시물에서 홍보하거나 주요하게 다루는 삼성 제품만 영어로 작성합니다.

핵심 규칙
1. 캡션, 영상, 이미지, 화면 내 텍스트에서 실제로 확인되는 공식 제품명을 사용합니다.
2. 제품 코드네임 매핑을 사용하지 않습니다.
3. QHB8, QH8, Q8, H8, B8 등 내부 코드로 변환하지 않습니다.
4. 공식 제품명이 확인되면 제품명을 그대로 기입합니다.
5. 정확한 모델명이 확인되지 않으면 더 구체적인 모델명, 세대, Ultra, Plus, Pro 등을 추측하지 않습니다.
6. 삼성 제품이 아닌 경쟁 제품은 Product에 포함하지 않습니다.
7. 제품이 확인되지 않으면 빈 문자열을 반환합니다.
8. 제품명에는 절대 Samsung (대소문자 구분 없이) 혹은 삼성이 들어가지 않습니다.

제품명 처리
- Galaxy Z Fold8이 확인되면 "Galaxy Z Fold8"
- Galaxy Z Flip8이 확인되면 "Galaxy Z Flip8"
- Galaxy Z Fold8 Series라고 명시되면 "Galaxy Z Fold8 Series"
- Galaxy Z Fold8과 Galaxy Z Fold8 Ultra가 함께 확인되면 "Galaxy Z Fold8 Series"
- Galaxy Buds4가 확인되면 "Galaxy Buds4"
- Pro가 명시된 경우에만 "Galaxy Buds4 Pro"
- 제품명 앞에는 절대 삼성, Samsung. samsung이 붙지 않습니다. 
- 제품명 처리 후 공식 명칭이 맞는지 확인합니다. (예: Watch Ultra 2로 뽑힌 경우 공식 명칭인 Galaxy Watch Ultra 2로 수정 해야합니다.)
- 입력에 Galaxy Tab, Galaxy Watch 등 다른 삼성 제품명이 명확히 확인되면 해당 이름을 사용합니다.

복수 제품
- 여러 제품 병기 시 Fold/Flip 순서로 통일하여 나열합니다. 
- 쉼표로 연결하지 않습니다.

예
"Product": "Galaxy Z Fold8\nGalaxy Z Flip8"

경품 제품
- 추첨, 심사, 선발 등으로 일부 참여자에게 지급되는 경품으로만 등장하더라도 게시물의 캠페인 구조를 이해하는 데 중요한 구체적 삼성 제품이면 Product에 포함할 수 있습니다.
- 경품 제품도 다른 제품과 동일하게 공식 제품명만 작성하며 별도의 태그를 붙이지 않습니다.
- 핵심 홍보 제품과 경품 제품을 혼동하지 않습니다.
- 동일 제품이 핵심 홍보 제품이면서 동시에 경품인 경우 Product에 같은 제품을 두 번 적지 않고 일반 제품명으로 한 번만 작성합니다. 경품 역할은 Description의 리워드 줄에서 표현합니다.
- 구매·사전예약·개통·trade-in 등 조건을 충족한 모든 적격 대상에게 보장되는 혜택으로만 등장하는 부수 제품은 독립적인 핵심 홍보 제품이 아니라면 Product에서 생략할 수 있습니다.

경쟁 제품
- Apple 또는 다른 브랜드 제품은 Product에서 제외합니다.
- 필요한 경우 Description에서 "경쟁 제품"으로 일반화합니다.


9. CXP Product Feature 작성 규칙

아래 허용 리스트에서 게시물의 핵심 소구 기능을 최대 3개 선택합니다.

- 허용 리스트에 존재하는 값만 사용
- 새로운 명칭 생성 금지
- 중요도 순으로 작성
- 여러 값은 \n으로 구분
- 세부 기능이 명확하면 세부값 사용
- 세부 기능이 불명확하고 상위 카테고리만 확인되면 {카테고리}_General 사용
- 동일 카테고리의 _General과 세부 기능을 함께 출력하지 않음
- 제품이 등장했다는 이유만으로 기능을 추정하지 않음
- 특정 기능이 드러나지 않는 론칭, 댓글 이벤트, 경품 게시물은 빈 문자열 가능
- 여러 앱 또는 화면을 동시에 사용하는 다중 작업 기능이 확인되는 경우 CXP Product Feature에는 반드시 정확히 "UI/UX_Multi Window"를 포함합니다.
- 위 경우 "UI/UX_General"로 대체하지 않으며, "UI/UX_Multi Window"와 "UI/UX_General"을 함께 출력하지 않습니다.
- CXP Product Feature의 공식 값은 "UI/UX_Multi Window"로 유지하되, Description에서는 해당 기능을 반드시 "멀티태스킹"으로 작성합니다. Description에서 "멀티윈도우", "Multi Window", "멀티 태스킹"이라는 표현을 사용하지 않습니다.

가능
"Camera_Horizontal Lock\nCamera_Super Steady"

불가능
"Camera_Horizontal Lock\nCamera_General"


10. Description 작성 규칙

Description은 Excel에서 바로 사용할 수 있는 한국어 보고서 문체로 작성합니다.

Description 작성 전 내부 정보 슬롯

Description 문장을 작성하기 전에 다음 정보를 내부적으로 먼저 식별합니다. 이 정보 슬롯 자체는 출력하지 않습니다.

* WHO: 핵심 협업 주체, 파트너, 인플루언서·배우·가수·모델·선수 등 핵심 인물과 확인된 역할

  * 캡션 또는 Conversation Stream에 @계정 형태로 개인 계정이 직접 태그되어 있는 경우 해당 계정이 콘텐츠의 출연자·협업자·홍보 주체인지 반드시 확인합니다.
  * 태그된 개인 계정이 콘텐츠의 핵심 출연자·협업자·홍보 주체로 확인되면 핵심 인물 후보로 반드시 반영합니다.
  * 단순 친구 태그 응모 조건, 콘텐츠와 직접적인 관계가 없는 계정, 브랜드·매체·장소 계정은 핵심 인물로 자동 판단하지 않습니다.

* WHAT: 중심 제품과 명확히 확인되는 핵심 기능

* HOW: 제품 또는 기능을 보여주는 구체적인 장면, 행동, 연출, 비유, 비교·시연 방식, 콘텐츠 형식

  * 단순히 어떤 기능이 등장했는지만 확인하지 않고 실제로 어떤 장면·행동·연출을 통해 해당 기능이나 제품 특성을 보여주는지 식별합니다.
  * 시각적 비유나 연출이 제품 특성을 전달하는 핵심 장치인 경우 해당 비유가 의미하는 제품 특성을 함께 파악합니다.

* ACTION: 댓글, 태그, 업로드, 퀴즈, 미션, 사전등록 등 실제로 확인되는 핵심 참여 행동

  * 댓글 작성을 유도하는 경우 단순히 "댓글 작성"으로만 파악하지 않고, 무엇을 댓글로 남기도록 요구하는지가 명시되어 있으면 해당 구체적인 내용을 함께 식별합니다.
  * 예: 가장 기대되는 기능, 선호 제품, 선호 스타일, 특정 질문에 대한 답변, 행운의 숫자 등
  * 해시태그 사용을 참여 행동으로 요구하는 경우 "지정 해시태그 사용" 여부만 식별하며, Description에는 구체적인 해시태그 문자열 자체를 작성할 필요가 없습니다.

* REWARD: 추첨·심사·선발 여부와 구체적으로 확인되는 경품 또는 리워드

  * 외화 현금, 디지털 머니 또는 기타 금액형 리워드가 있는 경우 외화 금액과 원화 환산 대상 여부를 함께 확인합니다.

* 각 슬롯에는 입력에서 확인되는 정보만 기록하고 확인되지 않은 정보는 추정하지 않습니다.

* Description 초안은 길이를 먼저 줄이지 않고, 확인된 WHO, WHAT, HOW, ACTION, REWARD 중 캠페인 이해에 필요한 정보를 가능한 한 모두 반영하여 작성합니다.

* 완전한 초안을 작성한 뒤에만 길이와 중복을 검토합니다.

기본 구조

* 일반 게시물: 본문 정확히 1문장
* 경품 게시물: 본문 정확히 1문장 + 다음 줄에 리워드 문구. 리워드 줄은 본문의 두 번째 문장으로 간주하지 않습니다.
* 불필요한 마침표 사용 금지
* Campaign Name을 그대로 반복하지 않음
* 주관적·과장 표현 금지
* 핵심 콘셉트를 문장 앞부분에 배치
* 먼저 글자 수 제한을 적용하지 않고 확인된 핵심 정보를 충분히 반영한 완결된 초안을 작성합니다.
* 완전한 초안 작성 후 필요한 경우에만 길이를 검사하며, 기본 120자 이내를 목표로 하되 필수 인플루언서 정보, 구체적인 장면·기능·참여 행동, 경품 정보가 필요한 경우 전체 160자를 초과할 수 있습니다.
* 길이 목표보다 핵심 정보의 정확성·구체성·완결성을 우선하며, 핵심 정보를 삭제해서 길이를 맞추지 않습니다.
* 글자 수를 맞추기 위해 문자열을 기계적으로 잘라내거나 문장 중간에서 종료하지 않습니다.
* 초안이 긴 경우 핵심 정보 우선순위에 따라 중복 표현과 부수적인 운영 정보를 먼저 압축하고, 핵심 정보를 유지한 상태에서 한 문장의 명사형 문장으로 다시 작성합니다.
* 길이 축약 시 날짜·링크·반복 CTA·부수적인 제품 나열·운영 정보를 먼저 줄이고 핵심 협업 주체, 주요 인물, 중심 제품, 핵심 기능·장면·참여 행동, 구체적인 리워드는 가능한 한 유지합니다.
* Description은 불완전한 조사·어미, 열린 괄호, 잘린 제품명, "…" 등으로 끝나지 않고 반드시 자연스러운 명사형으로 끝나야 합니다.

10.1 일반 본문 우선순위

1. 통신사·유통사·방송사·스포츠팀·브랜드 파트너·인플루언서 또는 주요 인물 등 핵심 협업 주체와 역할
2. 어떤 제품을 공개·소개·비교·강조하는 게시물인지
3. 구체적으로 어떤 장면·연출·행동·비유를 사용하여 제품을 보여주는지
4. 핵심 홍보 제품과 구체적인 기능
5. 참여 행동 및 구체적인 참여 내용
6. 구체적인 리워드
7. 부수적인 운영 정보

Description 구체성 최소 기준

* 입력에서 구체적인 기능, 장면, 행동, 연출, 비유, 비교 방식 또는 콘텐츠 형식이 확인되는 경우 "제품을 소개한 콘텐츠", "기능을 보여주는 콘텐츠", "제품을 홍보하는 콘텐츠"와 같은 일반적인 설명만으로 Description을 작성하지 않습니다.
* 구체적인 근거가 존재하는 경우 Description에는 중심 제품과 함께 최소 하나 이상의 구체적인 기능·장면·행동·연출·비유·비교 방식·콘텐츠 형식을 포함합니다.
* "소개", "홍보", "강조", "시연", "비교"를 사용할 때는 무엇을 어떤 기능·장면·행동 또는 방식으로 소개·홍보·강조·시연·비교하는지 함께 작성합니다.
* 명확한 세부 기능이 확인되면 단순히 "기능", "주요 기능", "다양한 기능"으로 일반화하지 않고 해당 기능 또는 실제 사용 장면을 구체적으로 반영합니다.
* 시각적 비유나 상징적 연출이 제품 특성을 설명하는 핵심 장치인 경우 단순히 해당 사물을 나열하지 않고 해당 비유를 통해 강조되는 제품 특성을 구체적으로 설명합니다.

예

* "Galaxy Z Fold8의 화면을 소개한 콘텐츠"보다 "Galaxy Z Fold8의 평평하고 매끄러운 화면을 빵에 버터를 바르는 모습에 비유하여 시각적으로 강조한 콘텐츠"를 우선합니다.
* "Galaxy Z Fold8 Ultra의 성능을 소개한 콘텐츠"보다 "Galaxy Z Fold8 Ultra의 대화면에서 알을 깨고 나온 드래곤이 포효하는 연출을 통해 Snapdragon 8 Elite 프로세서가 당사 제품에 탑재되어 있음을 강조한 콘텐츠"를 우선합니다.

댓글 및 참여 행동 구체성 규칙

* 댓글 작성이 게시물의 핵심 CTA인 경우 무엇을 댓글로 작성하도록 유도하는지가 캡션, 화면 내 텍스트 또는 영상에서 명시되어 있으면 해당 내용을 Description에 반드시 포함합니다.

  * 가장 마음에 드는 제품

  * 특정 주제에 대한 의견
* 댓글 내용이 명시되지 않고 단순히 댓글 작성을 요구하는 경우에만 "댓글 참여를 유도한 캠페인"처럼 일반적으로 작성할 수 있습니다.
* 해시태그 사용이 참여 행동으로 명시된 경우 해당 행동 자체는 필요 시 "지정 해시태그 사용을 유도한 캠페인"으로 표현할 수 있습니다.

* 캡션에 해시태그가 단순히 존재한다는 이유만으로 이를 참여 조건으로 판단하지 않습니다.

예

* "가장 기대되는 기능을 댓글로 남기도록 유도한 캠페인"

* "선호하는 스타일을 댓글로 남기고 지정 해시태그 사용을 유도한 캠페인"

Description 제품명 축약 규칙

아래 축약 규칙은 Description에만 적용합니다.

UI/UX_Multi Window 및 멀티태스킹 표기 규칙

* 단순히 "멀티태스킹 기능"이라고만 작성하지 않고, 확인 가능한 경우 대화면에서 여러 앱 또는 작업을 동시에 수행하는 구체적인 장면을 함께 반영합니다.

예

핵심 정보 보존 규칙

* 캡션, 화면 내 텍스트 또는 미디어에서 명확히 확인되는 협업 주체의 이름과 역할은 캠페인 이해에 중요하면 생략하지 않습니다.
* 캡션 또는 Conversation Stream에 @계정 형태로 핵심 인물이 태그되어 있고 해당 계정이 출연자·협업자·홍보 주체로 확인되면 해당 인물을 Description의 WHO 정보에서 누락하지 않습니다.
* 캡션 내 해시태그는 추가적인 인물 정보 또는 제품 정보를 검증하는 참고 근거로 사용할 수 있습니다.
* 협업 주체의 업종이나 역할이 확인되면 이름만 쓰지 않고 함께 작성합니다.
  예: "True dtac 5G"보다 "태국 통신사 True dtac 5G"를 우선합니다.
* 옥외 광고, 팝업, 매장 체험, 라이브 방송, 스포츠 경기 연계 등 구체적인 콘텐츠 형식 및 진행 유형도 핵심 콘셉트이면 유지합니다.
* Product 필드에 여러 제품이 있더라도 Description에 모든 제품을 기계적으로 나열하지 않습니다.
* Description에는 실제 콘텐츠에서 중심적으로 홍보되는 제품을 우선하고, 단순 노출·라인업·경품·주변 제품은 핵심 맥락이 아닐 경우 생략할 수 있습니다.
* 길이를 줄여야 할 때는 핵심 협업 주체와 역할, 주요 인물, 핵심 장면, 중심 제품, 핵심 기능, 구체적인 댓글 내용보다 부수적인 제품 나열과 운영 정보를 먼저 줄입니다.

Description 문장 종결 규칙

* Description 본문은 반드시 정확히 한 문장으로 작성하고 한국어 보고서형 명사형으로 종결합니다.
* "~한다", "~했다", "~된다", "~보여준다", "~소개한다", "~강조한다", "~유도한다", "~제공한다", "~증정한다"와 같은 서술형 종결을 사용하지 않습니다.
* 본문의 마지막 어절은 원칙적으로 명사 또는 명사형 표현이어야 합니다.
* 일반 본문의 권장 종결:
  "콘텐츠", "캠페인", "안내", "챌린지", "비교", "시연", "소개"
* 초안이 서술형 종결로 작성된 경우 마지막 어미만 삭제하거나 잘라내지 않고 문장 전체를 자연스러운 한 문장의 명사형 보고서 문체로 다시 작성합니다.
* 복수 절이 포함되더라도 마침표로 문장을 나누지 않고 하나의 완결된 문장으로 구성합니다.
* 경품 리워드 줄의 권장 종결:
  "증정", "제공"

예

* 권장: "태국 통신사 True dtac 5G와 함께 태국 인플루언서 Junior와 Mark (IG 팔로워 0.3M)가 Galaxy Z Fold8을 활용한 옥외 광고 장면을 통해 제품 디자인을 홍보하는 콘텐츠"
* 비권장: "태국 인플루언서 Junior와 Mark가 제품을 소개한다"
* 비권장: "Galaxy Z Fold8의 기능을 소개. 댓글을 유도한 콘텐츠"

10.2 인플루언서 및 핵심 인물 등장 시 필수 정보 형식

계정 유형에 무관하고(OWNED / INFLUENCER) 캠페인 또는 콘텐츠에 인플루언서·배우·가수·모델·선수 등 핵심 인물이 등장하며 정보가 확인되는 경우 Description 본문 앞부분에 다음 순서로 포함합니다.

{활동 국가} {인플루언서 특성 또는 구체적 직업} {인물명} ({채널} 팔로워 X.XM)

이 형식은 인물 정보의 최소 필수 형식입니다.

* 여기서 {활동 국가}는 법적 국적을 의미하지 않고 해당 인물이 주로 활동하는 국가 또는 시장을 의미합니다.
* 인물의 활동 국가는 Profile Location/Detailed Location, Bio, 공식 프로필 정보, 명확한 활동 시장 등 입력에서 확인되는 근거를 사용합니다.
* Publisher Type이 INFLUENCER이고 게시 계정과 Description의 인물이 동일하며 Publisher Country가 확정된 경우 Publisher Country를 해당 인물의 활동 국가로 사용할 수 있습니다.
* 확인된 활동 국가와 법적 국적을 동일한 개념으로 추정하지 않습니다.
* 통신사·유통사·브랜드 파트너, 옥외 광고·팝업·매장 체험 등 핵심 캠페인 맥락을 대신하거나 삭제하지 않습니다.

예

* 한국 라이프스타일 인플루언서 버금이 (X 팔로워 0.2M)가 ...
* 인도네시아 배우 Harry Vaughan (IG 팔로워 2.0M)이 ...
* 영국 테크 인플루언서 Alex Kim (YT 팔로워 1.3M)이 ...

인플루언서 특성 예

* 테크 인플루언서
* 라이프스타일 인플루언서
* 패션 인플루언서
* 뷰티 인플루언서
* 배우
* 가수
* 스포츠 선수

검증 규칙

인플루언서 국가·팔로워 누락 방지 우선 규칙

* 인플루언서·배우·가수·모델·선수가 Description의 핵심 인물인 경우 Description 작성 전에 활동 국가와 현재 게시 플랫폼의 팔로워 수 존재 여부를 반드시 먼저 확인합니다.

* 캡션에서 개인 계정이 직접 @태그되어 있고 해당 계정이 콘텐츠의 핵심 출연자·협업자·홍보 주체임이 확인되면 해당 인물의 프로필 정보를 핵심 인물 정보로 반드시 검토합니다.

* Publisher Type이 INFLUENCER이고 게시 계정과 Description의 인물이 동일하면 확정된 Publisher Country를 해당 인물의 활동 국가 정보로 사용할 수 있습니다.

* Publisher Type이 INFLUENCER이고 Sender Follower Count가 제공되며 게시 계정과 Description의 인물이 동일하고 현재 게시 플랫폼이 확인되면 길이 축약을 이유로 팔로워 정보를 생략하지 않습니다.

* 팔로워 수는 Description에서 항상 M 단위로 정규화합니다.

* 기본적으로 소수점 첫째 자리까지 표기합니다. 단, 0.1M 미만에서는 값이 0.0M으로 소실되지 않도록 필요한 경우 소수점 둘째 자리까지 사용합니다.

* 예: 2,000,000 → 2.0M, 836,000 → 0.8M, 101,000 → 0.1M, 58,000 → 0.06M, 33,000 → 0.03M

* Sender Follower Count가 K, 만, 천 단위 또는 원시 정수로 제공되어도 동일한 M 단위로 변환합니다.

* 활동 국가 또는 팔로워 수가 입력에 명시적으로 존재하는데 Description에서 누락하는 것을 허용하지 않습니다. 단, 해당 정보가 다른 인물의 정보이거나 현재 게시 플랫폼과 대응하지 않는 경우에는 사용하지 않습니다.

* 활동 국가, 특성, 이름, 채널, 팔로워 수는 입력에서 확인되는 정보만 사용합니다.

* 인물 이름은 프로필 정보, 캡션, 화면 내 텍스트, 태그 등 명시적 근거로 검증합니다.

* 얼굴이나 외형만으로 인물 이름을 추정하지 않습니다.

* 배우·가수·모델·선수 등 구체적인 직업이 확인되면 일반적인 "인플루언서"보다 해당 직업을 우선 사용합니다.

* "크리에이터" 또는 "creator"라는 표현은 사용하지 않습니다.

* 활동 국가·특성·이름이 확인되면 팔로워 수가 없더라도 "{활동 국가} {특성} {이름}" 형식을 유지합니다.

* Sender Follower Count는 현재 게시 플랫폼에서 게시물을 업로드한 계정의 팔로워 수입니다.

* Publisher Type이 INFLUENCER이고 게시 계정과 Description에서 언급하는 인물이 동일하면 Sender Follower Count를 해당 인물의 팔로워 수로 사용합니다.

* 이 경우 Sender Follower Count가 제공되고 플랫폼이 확인되면 "({채널} 팔로워 X.XM)" 형식을 생략하지 않습니다.

* Publisher Type이 OWNED이면 Sender Follower Count는 Samsung 공식 게시 계정의 팔로워 수이므로 콘텐츠 속 등장 인물에게 절대 적용하지 않습니다.

* OWNED 게시물의 등장 인물 팔로워 수는 해당 인물 본인의 동일 플랫폼 팔로워 수가 캡션, 화면 내 텍스트, 태그 또는 별도 인물 메타데이터에서 명시적으로 확인되는 경우에만 사용합니다.

* 팔로워 수의 플랫폼이 현재 게시 플랫폼과 다르거나 출처가 불명확하면 괄호 전체를 생략합니다.

* 팔로워 수를 임의 계산하거나 추측하지 않습니다.

* 정보가 없는 요소를 채우기 위해 다른 정보를 만들어내지 않습니다.

복수 인물 형식

* 국가와 특성이 같은 복수 인물은 "{국가} {특성} {이름1}와 {이름2}"로 작성할 수 있습니다.
* 각 인물의 동일 플랫폼 팔로워 수가 각각 확인되면 이름별로 괄호를 붙입니다.
  예: "태국 인플루언서 Junior (IG 팔로워 1.2M)와 Mark (IG 팔로워 0.8M)가 ..."
* 게시 계정의 Sender Follower Count 하나를 복수 등장 인물 모두의 팔로워 수로 사용하지 않습니다.

일부 정보가 없을 때

* 팔로워 수만 확인되지 않으면 괄호 전체를 생략하되 활동 국가·특성·이름은 유지합니다.
* 이름이 확인되지 않으면 이름을 만들지 않고 일반화합니다.
  예: "한국 테크 인플루언서가 ..."
* 활동 국가도 확인되지 않으면 국가를 생략합니다.
* Publisher Type이 INFLUENCER인데 계정명과 인물명, 직업 또는 활동 국가 중 일부가 비어 있으면 확인 가능한 정보는 최대한 유지하고 해당 불확실성이 최종 결과의 정확도에 실질적으로 영향을 주는 경우 Requires Manual Review를 true로 설정합니다.
* 불확실한 정보를 억지로 채우지 않습니다.

채널 표기

* Instagram: IG
* X/Twitter: X
* TikTok: TT
* YouTube: YT
* Facebook: FB

중요

* Publisher Type은 게시 계정 기준입니다.
* Publisher Type이 INFLUENCER이면 게시 계정 자체의 검증된 활동 국가·직업 또는 특성·이름을 Description 앞부분에 우선 반영합니다.
* 삼성 공식 계정이 배우·가수·인플루언서를 등장시킨 경우 신원·직업·출연 여부가 캡션, 해시태그, 화면 내 텍스트, 음성, 태그된 계정, 프로필 또는 별도 인물 메타데이터 등 명시적 근거로 확인되면 검증된 인물 정보를 Description에 포함합니다.
* 이름과 직업 또는 특성은 각각 확인된 정보만 사용하며 확인되지 않은 요소를 다른 정보로부터 추정하지 않습니다.
* 얼굴이나 외형만으로 인물을 식별하거나 직업을 추정하지 않습니다.
* 이 경우에도 Publisher Type은 OWNED이며 Sender Follower Count는 등장 인물 정보에 사용하지 않습니다.

10.3 Giveaway/경품 게시물 형식

이 섹션에서 경품은 추첨, 심사, 선발 등으로 일부 참여자에게 지급되며 참여 또는 구매만으로 지급이 보장되지 않는 리워드를 의미합니다.

구매, 사전예약, 개통, trade-in 등 조건을 충족한 모든 적격 대상에게 보장되는 사은품·할인·쿠폰·번들·추가 보상은 경품/Giveaway로 분류하지 않습니다.

* Giveaway/경품 게시물로 판단하려면 추첨·심사·선발 등의 비보장 지급 구조뿐 아니라 실제 지급되는 구체적인 경품 또는 리워드의 종류·제품명·금액·쿠폰·상품 등 최소 하나의 지급 내용이 명시적으로 확인되어야 합니다.
* 댓글 작성, 좋아요, 팔로우, 친구 태그, 해시태그 사용 등 참여 행동만 확인되고 구체적인 경품 또는 리워드 내용이 확인되지 않으면 Giveaway/경품 게시물로 판단하지 않습니다.
* "당첨 기회", "경품 제공", "prize", "win" 등 경품 가능성만 언급되고 실제 지급 내용이 확인되지 않는 경우에도 Giveaway/경품으로 확대하지 않습니다.
* 이 경우 Description에 "\n→ " 리워드 줄을 추가하지 않으며 "경품 상세 내용 미확인"이라는 문구를 출력하지 않습니다.

위 조건을 모두 충족하여 경품 구조와 구체적인 경품 내용이 명확한 경우 Description은 반드시 다음 형식을 사용합니다.

{캠페인 핵심 내용과 참여 행동을 설명한 본문}
→ {구체적인 경품 설명}

JSON 문자열 형식
"Description": "본문\n→ 경품 설명"

리워드 줄 작성 규칙

* 반드시 새 줄에서 "→ "로 시작합니다.
* 추첨 방식, 당첨 인원, 1인당 지급 내용, 경품명, 금액이 확인되면 가능한 범위에서 포함합니다.
* 경품이 여러 개면 핵심 경품을 한 줄에서 간결하게 정리합니다.
* 구체적인 경품 정보가 확인되지 않으면 만들어내지 않습니다.
* 물리적 제품이나 상품의 시장 가격을 임의로 추정해 원화 금액을 생성하지 않습니다.

외화 금액 리워드 원화 환산 규칙

* 외화 현금, 디지털 머니, 현금성 포인트 등 금액 자체가 리워드인 경우 원래 외화 금액과 함께 원화 환산액을 반드시 괄호 안에 표기합니다.
* 형식은 "{외화 금액} (약 {원화 환산액})"으로 작성합니다.
* 원화 환산액이 1만원 이상이면 가독성을 위해 만원 단위의 근사값으로 작성합니다.
  예: "(약 8만원)", "(약 15만원)"
* 원화 환산액은 분석 시점에 입력으로 제공되거나 확인 가능한 최신 KRW 환율을 사용해 계산합니다.
* 1인당 지급 금액이면 1인당 외화 금액을 원화로 환산하고, 총 지급 금액이면 총액을 기준으로 환산합니다.
* 복수 당첨자의 총액과 1인당 금액을 혼동하지 않습니다.
* 원래 외화 금액은 삭제하지 않고 반드시 함께 유지합니다.
* 환율 계산 과정이나 산식은 Description에 출력하지 않습니다.
* 상품·제품 자체를 경품으로 지급하는 경우 해당 제품의 가격을 임의로 조사·추정하여 원화 금액을 추가하지 않습니다.

좋은 예

* → 추첨을 통해 10명에게 네이버페이 3만원권 증정
* → 추첨을 통해 2명에게 각 100만 루피아 (약 8만원) 증정
* → 추첨을 통해 25명에게 커피 쿠폰 증정
* → 심사를 통해 우승자에게 Galaxy Buds4 증정
* → 추첨을 통해 Galaxy Z Flip8 또는 총 200만 루피아 (약 15만원) 상당의 디지털 머니 증정

경품 여부가 불명확한 경우

* 구체적인 경품 또는 리워드 지급 내용이 확인되지 않으면 경품 게시물로 분류하지 않고 일반 게시물 또는 확인된 참여형 캠페인 규칙을 적용합니다.
* "\n→ 경품 상세 내용 미확인"을 생성하지 않습니다.
* 경품 관련 근거가 서로 상충하여 최종 캠페인 분류 또는 Description의 정확도에 실질적인 영향을 주는 경우에만 Requires Manual Review = true로 설정합니다.

구매·사전예약 등 보장형 혜택

* 구매, 사전예약, 개통, trade-in 등 조건을 충족한 모든 적격 대상에게 혜택이 보장되면 Giveaway/경품 게시물로 확대하지 않습니다.
* 이 경우 "\n→ " 리워드 줄을 사용하지 않고 Description 본문 1문장 안에서 조건과 혜택을 설명합니다.
* 예: "Galaxy Z Fold8 사전예약 구매자에게 Galaxy Buds4를 제공하는 사전예약 혜택 안내"
* 예: "Galaxy Z Fold8 구매 시 trade-in 추가 보상과 할인 혜택을 안내한 콘텐츠"

경품이 없는 일반 게시물에는 화살표 줄을 사용하지 않습니다.

10.4 참여형 캠페인 판단

다음이 명확하면 참여형 캠페인

* 응모 조건
* 해시태그 챌린지
* 사용자 콘텐츠 업로드
* 구체적인 댓글·투표·선택 행동
* 추첨 또는 리워드
* 이벤트 참여 절차
* 사전등록이 추첨·선발 또는 별도 참여 절차와 직접 연결된 경우

다음만 있는 경우 참여형 캠페인으로 확대하지 않음

* 일반적인 좋아요/공유 요청
* 구체적인 참여 구조가 없는 일반적인 댓글 유도
* 조건이 불명확한 CTA
* 추첨·리워드와 연결되지 않은 일반 안내
* 구매·사전예약·개통·trade-in 조건 충족 시 모든 적격 대상에게 보장되는 혜택
* 추첨·선발 없이 사전등록만으로 확정적으로 제공되는 혜택

경품 없는 댓글·해시태그 CTA 표현

* 경품·추첨·심사·선발 없이 댓글 작성 또는 지정 해시태그 사용을 명시적으로 유도하는 경우 Giveaway·Challenge·경품형 캠페인으로 확대하지 않습니다.
* 다만 해당 행동이 게시물의 핵심 CTA이면 Description에서 생략하지 않습니다.
* 무엇을 댓글로 작성하도록 요구하는지가 확인되는 경우 "댓글 참여를 유도"처럼 일반화하지 않고 해당 내용을 구체적으로 작성합니다.
* 댓글만 요구하지만 구체적인 답변 내용이 확인되지 않는 경우에만 "댓글 참여를 유도한 캠페인"처럼 작성합니다.
* 특정 해시태그 사용을 요구하는 경우 "지정 해시태그 사용을 유도한 캠페인"처럼 행동만 표현하고 실제 해시태그 문자열은 Description에 작성하지 않습니다.
* 댓글의 구체적인 내용과 해시태그 사용이 모두 요구되는 경우 댓글 내용은 구체적으로 유지하고 해시태그는 "지정 해시태그 사용"으로 일반화합니다.
* 경품이 없으므로 "\n→ " 리워드 줄을 추가하지 않습니다.

예

* "가장 기대되는 기능을 댓글로 남기도록 유도한 캠페인"
* "가장 마음에 드는 제품을 댓글로 선택하도록 유도한 캠페인"
* "선호하는 스타일을 댓글로 남기고 지정 해시태그 사용을 유도한 캠페인"

10.5 CTA 압축

여러 참여 절차를 전부 나열하지 않습니다.
핵심 응모 조건을 중심으로 압축합니다.

* CTA를 압축하더라도 댓글에 작성해야 하는 구체적인 답변·선택·숫자·문구가 확인된 경우 해당 내용은 압축 대상에서 제외합니다.
* "댓글 작성"이라는 행동 자체보다 "무엇을 댓글로 작성해야 하는지"를 우선 보존합니다.
* 구체적인 해시태그 문자열은 Description에 유지할 필요가 없으며 "지정 해시태그 사용"으로 일반화할 수 있습니다.
* 핵심 조건이 아니면 좋아요, 저장, 일반 공유, 알림 설정, 반복 링크 안내를 생략할 수 있습니다.

예

* 해시태그 사용 + 사전등록 + 링크 클릭
  → 지정 해시태그 사용 및 Galaxy Unpacked 사전등록
* 팔로우 + 좋아요 + 친구 태그 + 가장 기대되는 기능 댓글
  → 가장 기대되는 기능을 댓글로 남기고 친구 태그
* 저장 + 공유 + 가장 마음에 드는 제품 댓글
  → 가장 마음에 드는 제품을 댓글로 작성

10.6 표현 원칙

Description 표기 통일 규칙

* 아래 표기 규칙은 Description에만 적용합니다. Campaign Name, Product, Publisher Type, Publisher Country 등 다른 필드의 공식 명칭은 기존 규칙을 유지합니다.
* Description에서 Samsung 또는 삼성이라는 회사·브랜드 주체를 지칭할 필요가 있는 경우 반드시 "당사"로 표기합니다.
* 단, Publisher Type이 OWNED라는 이유만으로 게시 계정 자체를 Description의 주체로 삽입하지 않습니다.
* Description은 "당사", "당사가", "당사의", "당사 계정이", "당사 공식 계정이"로 시작하지 않습니다.
* "한국 당사 계정이", "인도네시아 당사 계정이", "태국 당사 공식 계정이" 등 "{국가명} + 당사 계정" 형태를 Description의 주어로 사용하지 않습니다.
* OWNED 게시물은 중심 제품, 핵심 기능·장면, 핵심 인물, 협업 파트너 또는 콘텐츠 형식을 문장 앞부분에 배치합니다.
* Samsung이라는 기업 주체가 실제 콘텐츠 의미상 필요한 경우에만 문장 중간에서 "당사"를 사용합니다.

권장

* "Galaxy Z Fold8의 평평하고 매끄러운 화면을 빵에 버터를 바르는 모습에 비유하여 시각적으로 강조한 콘텐츠"
* "Galaxy Z Fold8 Ultra의 대화면에서 알을 깨고 나온 드래곤이 포효하는 연출을 통해 Snapdragon 8 Elite 프로세서가 당사 제품에 탑재되어 있음을 강조한 콘텐츠"

비권장

* "당사가 Galaxy Z Fold8의 화면을 소개한 콘텐츠"

* "인도네시아 당사 계정이 Galaxy Z Fold8 Ultra를 소개한 콘텐츠"

* "태국 당사 공식 계정이 제품 기능을 강조한 콘텐츠"

* Description에서는 "크리에이터" 및 "creator"라는 표현을 절대 사용하지 않습니다.

* 구체적인 직업 또는 특성이 확인되면 배우, 가수, 스포츠 선수, 모델, 테크 인플루언서, 라이프스타일 인플루언서 등 확인된 표현을 사용합니다.

* 구체적인 직업 또는 특성이 확인되지 않고 개인형 influencer임만 확인되면 "인플루언서"로 작성합니다.

* Description에서 iPhone은 반드시 "iP"로 표기합니다.

* Description에서 Apple은 반드시 "A社"로 표기합니다.

* Description에서 중국 브랜드(예: Xiaomi, Huawei)는 반드시 "C Brand"로 표기합니다.

* Description에서 갤럭시 언팩, Galaxy unpacked, Galaxy Unpack 등 Galaxy Unpacked 행사를 지칭할 때는 반드시 정확히 "Galaxy Unpacked"로 표기합니다.

* 공식 삼성 제품명 자체에 포함된 Galaxy 등 제품 고유명은 변경하지 않습니다.

* 위 표기는 번역이나 문장 축약 과정에서도 일관되게 유지합니다.

구체적 표현

12. 권장 Description 템플릿
Description 작성 시 먼저 게시물에서 반드시 보존해야 하는 핵심 정보를 확인한 뒤, 게시물이 가장 중심적으로 전달하는 콘텐츠 구조를 기준으로 12.1~12.9 중 Primary Type 1개를 선택합니다.
Description 작성 순서는 다음과 같습니다.
(1)	Required Information 확인: 입력에서 확인되는 경우 Description에 반드시 보존해야하는 정보
A.	10.2에 따라 Description에 포함해야 하는 핵심 인물 정보
B.	핵심 파트너 및 역할
C.	핵심 제품
D.	핵심 기능 또는 제품 특성
E.	구체적 사용 장면 또는 콘텐츠 형식
F.	핵심 참여 행동
G.	경품 여부, 선정 방식, 당첨 인원 및 리워드
(2)	Primary Type 선택
A.	12.1~12.9 중 게시물이 가장 중심적으로 전달하는 콘텐츠 유형 1개를 선택합니다.
B.	Primary Type은 Description의 본문 구조를 결정합니다.
C.	인플루언서 여부, 참여 여부, Giveaway 여부 자체는 Primary Type을 결정하지 않습니다.
(3)	Description 조합
A.	1단계에서 확인한 Mandatory Element를 유지한 상태에서 선택된 Primary Type의 문장 구조를 적용합니다.
B.	Mandatory Element는 Primary Type 선택 과정에서 삭제하거나 일반화하지 않습니다.
C.	특히 핵심 인물이 확인된 경우 10.2의 인물 정보는 선택 사항이 아니라 필수 요소이며, 선택된 본문 유형의 앞부분에 결합합니다.
D.	참여 행동과 Giveaway 정보도 각각 10.3~10.5의 규칙에 따라 본문 또는 리워드 줄에 결합합니다.
하나의 게시물이 여러 유형의 요소를 포함하는 경우, Description의 기본 문장 구조를 결정하는 핵심 유형 1개를 Primary Type으로 선택합니다. 다른 유형의 요소가 캠페인 이해에 중요한 경우 Secondary Element로 문장에 함께 반영할 수 있습니다.

•	제품 기능 설명이 함께 있더라도 구매 혜택 전달이 게시물의 핵심 목적이면 구매 프로모션형을 우선합니다.
12.9 일반 소개형
적용 기준
위 유형에 명확하게 해당하지 않고 제품의 여러 기능이나 특징을 종합적으로 소개하는 경우
권장 템플릿
{제품명}의 {주요 기능/특징}을 소개하며 {핵심 소구점}을 강조한 콘텐츠
작성 원칙
•	다른 구체적인 유형으로 분류할 수 있는 경우 일반 소개형보다 해당 유형을 우선합니다.
•	판단이 어려운 내용을 억지로 특정 유형에 맞추기 위한 용도로 사용하지 않습니다.
•	여러 기능을 단순 나열하지 않고 게시물에서 중심적으로 다루는 특징을 우선합니다.
12.10 주체·참여·Giveaway 조합 규칙
12.1~12.9에서 선택한 Primary Type은 본문의 의미 구조를 결정하며, 인물·참여·Giveaway 정보는 아래 규칙에 따라 반드시 조합합니다.
적용 우선순위
핵심 인물 없음 + 참여 없음 + Giveaway 없음 → 일반 콘텐츠
핵심 인물 있음 + 참여 없음 + Giveaway 없음 → 인플루언서 또는 주요 인물 콘텐츠
핵심 인물 없음 + 참여 있음 + Giveaway 없음 → 참여형 콘텐츠
핵심 인물 있음 + 참여 있음 + Giveaway 없음 → 인플루언서 참여형 콘텐츠
핵심 인물 없음 + Giveaway 있음 → Giveaway 콘텐츠
핵심 인물 있음 + Giveaway 있음 → 인플루언서 Giveaway 콘텐츠

여러 조건이 동시에 충족되면 더 구체적인 조합을 반드시 적용합니다.
예:
핵심 인물 + 댓글 참여 → 일반 참여형이 아니라 인플루언서 참여형
핵심 인물 + 경품 → 일반 Giveaway가 아니라 인플루언서 Giveaway
핵심 인물이 있는 경우
{10.2에 따른 핵심 인물 정보} + {선택된 Primary Type에 따른 핵심 내용}
참여가 있는 경우
{선택된 Primary Type에 따른 핵심 내용}을 소개하고, {핵심 참여 행동}을 유도한 캠페인
핵심 인물과 참여가 모두 있는 경우
{10.2에 따른 핵심 인물 정보} + {선택된 Primary Type에 따른 핵심 내용}을 소개하고, {핵심 참여 행동}을 유도한 캠페인
Giveaway가 있는 경우
본문
→ {선정 방식}을 통해 {구체적 대상 또는 인원}에게 {구체적 리워드} 증정
인물 정보는 10.2, 참여 행동은 10.4~10.5, Giveaway 리워드는 10.3 규칙을 따릅니다. 확인되지 않은 정보는 생성하지 않되, 확인된 핵심 인물·참여 행동·리워드는 임의로 삭제하지 않습니다.

12.11 Primary Type 선택 우선 원칙
Primary Type은 게시물이 최종적으로 무엇을 가장 중심적으로 소개·전달하는지를 기준으로 선택합니다.
실제 기능 사용 장면이 중심 → 기능·활용형
디자인, 두께, 무게, 색상, 화면비 등 제품 자체 특성이 중심 → 디자인 및 제품 특성형
제품·조건 간 직접 비교 또는 반복 테스트가 중심 → 비교·검증형
제3자의 평가, 첫인상, 리뷰 경험이 중심 → 리뷰·언박싱·평가형

외부 브랜드·IP·문화 요소를 활용한 연출 자체가 중심 → 협업·콘셉트형
특정 장소 방문, 제품 체험, 팝업·전시·매장 경험이 중심 → 행사·체험형
제품 공개, 출시, 판매 시작, Galaxy Unpacked 예고가 중심 → 출시·티징형
할인, 보상판매, 사전예약, 캐시백 등 구매 혜택이 중심 → 구매 프로모션형
위 유형 중 어느 하나가 명확히 중심이 아닌 종합 제품 소개 → 일반 소개형

주의:
인플루언서 여부, 참여 여부, Giveaway 여부는 Primary Type을 결정하지 않지만 Description에서 생략 가능한 정보라는 의미는 아닙니다.
해당 정보가 확인되면 12.10에 따라 선택된 Primary Type과 반드시 결합합니다.
Primary Type 선택으로 인해 10.2~10.5에서 필수로 요구하는 인물, 참여 행동, 리워드 정보가 삭제되어서는 안 됩니다.

14. 내부 검증 절차

응답 전 내부적으로 다음을 확인합니다.

1. 핵심 제품
- 실제로 확인되는 삼성 제품만 선택
- 코드네임으로 변환하지 않음
- 복수 제품은 \n으로 구분
- 경쟁 제품은 Product에서 제외
- 경품으로만 등장하는 삼성 제품도 공식 제품명만 사용하며 별도의 태그를 붙이지 않음
- 구매·사전예약 조건 충족 시 보장되는 혜택으로만 등장하는 부수 제품은 핵심 홍보 제품이 아니면 Product에서 생략 가능

2. 핵심 콘셉트
- 제품 소개, 기능, 비교, 인물, 참여, 사전등록, 경품 중 핵심 유형 파악
- 사진·영상 제작, 퀴즈·수수께끼, 미션 등 실질 활동형 참여인지 확인하고 해당되면 Campaign Name의 Challenge 사용 여부를 재검토
- 단순 댓글/좋아요/리트윗형 참여와 활동형 Challenge를 구분
- 경품 없이 댓글·해시태그 사용을 명시적으로 유도하면 Giveaway로 확대하지 않고 Description에 해당 CTA를 "~를 유도한 캠페인" 형태로 반영
- 댓글·좋아요·팔로우·친구 태그 등 참여 행동만 있고 구체적인 경품 또는 리워드 지급 내용이 확인되지 않으면 Giveaway로 판단하지 않으며 "경품 상세 내용 미확인"을 생성하지 않음
- 구매·사전예약 등 보장형 혜택과 구체적인 리워드가 확인된 추첨·심사·선발형 경품을 구분
- 공식 quote 또는 주요 전달 메시지가 Campaign Name에 활용 가능한지 확인
- 미디어 타입이 unresolved/unknown이면 제공된 게시물 텍스트, URL, 계정 메타데이터와 실제 사용 가능한 미디어만 사용하고 존재하지 않는 미디어 내용을 추측하지 않음
- 통신사·유통사·브랜드 파트너 등 명시된 협업 주체의 이름과 역할을 확인
- 옥외 광고·팝업·매장 체험·라이브 방송 등 구체적인 콘텐츠 형식을 확인
- Product 필드의 모든 제품을 Description에 기계적으로 나열하지 않고 중심 제품을 선별

3. 게시자
- 게시 계정이 OWNED, INFLUENCER, UNKNOWN 중 무엇인지 판단
- 콘텐츠 속 인플루언서와 게시 계정 유형을 구분
- 게시 국가를 허용 Country 문자열로 정확히 결정
- Subsidiary는 판단하지 않음

4. Description
- 작성 전에 WHO, WHAT, HOW, ACTION, REWARD 정보 슬롯을 내부적으로 먼저 확인하고, 확인된 핵심 정보를 충분히 반영한 완전한 초안을 먼저 작성
- 인플루언서·배우 등 핵심 인물이 등장하면 검증된 활동 국가·특성 또는 직업·이름을 지정 형식으로 포함
- Publisher Type이 INFLUENCER이고 활동 국가 정보가 확인되면 Description 앞부분의 국가 표기를 누락하지 않음
- Publisher Type이 INFLUENCER이고 Sender Follower Count가 제공되면 게시 계정 인물과의 동일성 및 플랫폼을 확인한 뒤 팔로워 형식을 적용
- 현재 게시 플랫폼의 팔로워 수가 확인되면 반드시 M 단위로 정규화하여 Description에 포함
- Description에서 Samsung/삼성→당사, iPhone→iP, Apple→A社, 중국브랜드→C Brand, 갤럭시 언팩 관련 표현→Galaxy Unpacked 표기 규칙을 준수
- Description을 당사/당사가/당사의로 시작하지 않음
- Description에서 "크리에이터" 또는 "creator"를 사용하지 않음
- CXP가 "UI/UX_Multi Window"인 경우 Description에서는 해당 기능을 "멀티태스킹"으로 표현하고 "멀티윈도우", "Multi Window", "멀티 태스킹"을 사용하지 않음
- Publisher Type이 OWNED이면 Sender Follower Count를 등장 인물에게 적용하지 않음
- 확인된 구체적 직업을 일반적인 "인플루언서"로 바꾸지 않음
- 통신사 등 핵심 협업 주체의 역할과 이름, 구체적인 콘텐츠 형식을 누락하지 않음
- 중심 제품보다 부수적인 제품을 과도하게 나열하지 않음
- 추첨·심사·선발 구조와 구체적인 경품 또는 리워드 지급 내용이 모두 확인된 경우에만 다음 줄에 → 리워드 형식 적용
- 구체적인 경품 지급 내용이 확인되지 않으면 Giveaway로 판단하지 않고 → 리워드 줄 및 "경품 상세 내용 미확인"을 생성하지 않음
- 구매·사전예약 등 보장형 혜택에는 → 리워드 형식을 사용하지 않음
- 구체적인 기능·장면·행동이 확인되는 경우 일반적인 "제품을 소개한 콘텐츠" 수준으로 축약하지 않음
- 먼저 핵심 정보를 충분히 반영한 후 필요한 경우에만 길이를 검사하며, 글자 수 때문에 핵심 정보를 삭제하거나 문장을 자르지 않음
- Description 본문이 정확히 한 문장인지 확인하고, 서술형 종결이면 마지막 어미만 제거하지 않고 전체 문장을 자연스러운 명사형 문장으로 재작성
- 확인되지 않은 이름, 특성, 팔로워 수, 경품을 만들지 않음

5. 길이와 형식
- Product와 CXP 복수 값은 \n
- Description의 줄바꿈은 경품 리워드 줄에서만 사용
- JSON key와 타입 준수
